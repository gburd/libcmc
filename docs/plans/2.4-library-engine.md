# Plan: the library engine for pg_chain (2.4)

pg_chain checks its protocol cores with the library engine (`cmc.h`,
`CmcCore`): the cores are compiled once and linked both into the
PostgreSQL extension and into the checker.  Its asks after 2.2.0 (time,
a node that never crashes, timers with an argument, scale, and history
properties) all concern that engine; process mode cannot run PostgreSQL
yet.  This plan answers them, in this order, with the decisions Greg
made on 2026-11-24.  The rule from 2.0 holds: refused until modelled,
then exact or explicitly approximate, with a gate.

Every change to `cmc.h` is additive: a new field or hook that is zero
or NULL keeps today's behaviour, so the existing cores and their
distinct-state counts do not change.  `test/pgchain/` holds a copy of
pg_chain's cores and models (Apache-2.0) as the acceptance and scale
benchmark, with pg_chain's own gate rows and counts.

## 1. A node that never crashes

`CmcCore.crashable(cfg, node)`, like `clients()`: from cfg only, NULL
means every node may crash.  CRASH is not offered for a node it
excludes.

## 2. Time: clocks, deadlines and drift

- The environment holds a clock per node and a reference time.
  `CmcEvent.now` carries the node's clock reading into every event, so
  `step()` stays pure.  Properties read `cmc_clock(w, node)` and
  `cmc_now(w)`.
- `CMC_OUT_SET_TIMER` takes a duration (`CmcOutput.dur`, in the core's
  time unit).  A timer with duration 0 behaves as today (fires at any
  point), so existing cores are unchanged.  A timer with a duration
  fires at its deadline, offered only in deadline order per node, as in
  process mode.
- `--drift R` (per thousand), with process mode's semantics: when a
  deadline fires and its node's clock moves by D, every other clock
  moves by D, or one other node's clock moves at the slowest or fastest
  rate the drift allows.  Rates in between and two clocks off the
  common rate at once are not explored; the docs say so.
- **Finite state, step one: a horizon.**  `--max-time T`: a world whose
  reference time passed T is not expanded, and a run that cut one ends
  INCOMPLETE, never PASS.
- **Finite state, step two: declared time fields.**
  `CmcCore.time_fields(cfg, node, off, max)` lists the offsets of the
  64-bit clock readings in a node's state (absolute times the core
  stored, such as a lease's valid_until).  With it the engine stores
  every time relative to the reference clock and saturates gaps beyond
  the largest constant that matters (`--time-bound`, or the largest
  timer duration plus the drift), the timed-automata extrapolation, so
  worlds that differ only in when things happened merge and the search
  is exhaustive without a horizon.  A field the core forgets to declare
  is a hole the gate cannot see (as for the state hook in process mode),
  so a determinism-style check runs each search twice with all times
  shifted and must get the same counts.
- Gate: a port of process mode's leasedrift row to a core: correct with
  L(1 - rho), caught with no margin when the holder's clock runs slow,
  passing at drift 0.

## 3. Timers and wakes with an argument

Timers and wakes move from bit masks to tables of `{id, arg, deadline}`
entries, sorted canonically, with capacity options (`--timer-cap`,
`--wake-cap`).  `CmcOutput.arg2` is the argument; `CmcEvent.arg2` brings
it back.  Equal deadlines with different arguments are distinct pending
events.

## 4. History

- **The request log.**  The engine records, per client request, the
  node, the request number, whether it was answered and the answer, and
  the real-time precedence relation (which requests were answered
  before which others were invoked), not step numbers, so two paths to
  one state still merge.  Properties read it through `cmc_request(w, i,
  ...)` and `cmc_precedes(w, i, j)`; a linearizability check of tail
  reads needs no more.
- **History variables.**  `CmcModel.history_size` bytes the engine
  keeps with the world and hashes, and `CmcModel.history(pre, action,
  post, ghost)`, run after every step, that updates them: a TLA+ history
  variable, outside the cores and their purity gate.  "Once chosen, a
  value stays chosen" becomes an invariant over it.

## 5. Scale

Measured target: pg_chain's two-candidate Paxos row (187,043,769
distinct states, 770 s) and its biggest chain row (109,705,420, 28.5 GB).

- **Memory first.**  Measure where the 28.5 GB goes.  Then: parents by
  index rather than fingerprint, and a BFS queue that spills to disk, so
  a row that does not fit degrades instead of failing.
- **Symmetry declared by the core.**  The cfg names interchangeable node
  sets, and `CmcCore.permute(cfg, perm, node, state)` and
  `permute_msg(cfg, perm, body, len)` rewrite node ids inside a state
  and a message.  The world is reduced to a canonical representative.
  Gate: verdicts identical with symmetry on and off on every model, and
  counts equal to the orbit count where it is computable.
- **Parallel BFS** with exact counts and shortest counterexamples: each
  level is expanded in parallel, and the counterexample reported is the
  first in a fixed order at the shallowest level.
- **Partial-order reduction** for deliveries to different nodes, last
  and behind a gate that compares results with it on and off; not for
  steps a declared action property reads.
