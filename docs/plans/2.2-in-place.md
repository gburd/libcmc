# Plan: an in-place checker (2.2 and after)

Greg Burd's notes of 2026-11-19 ("What libcmc needs to be an in-place
model checker", written after evaluating 2.1.0) set the goal: take a
program exactly as it ships and explore every behaviour the operating
system and the network could produce, up to a bound.  They give two
tests.  The soundness test asks that every bug a real host can produce
at the bound be reachable.  The reach test asks that pg_chain, which is
PostgreSQL itself on three hosts, run under the checker.

This plan takes the notes' items in the order they ask for, adds the
gaps 2.1 left open, and says for each what lands in 2.2 and what does
not.  The rule from 2.0 holds for every item: refused until modelled,
then exact or explicitly approximate, with a row in the qualification
table and a gate.

## What 2.2 does

1. **A crash between any two effectful calls** (notes item 1).  Done
   on `pr/2.2`.  While crash budget is left, a single-threaded node
   stops after each write or send on a checker-owned fd, each close of
   one, and each durable write; the search may crash it there or run it
   on.  No invariant is checked at such a point (the program's state
   hook lags its effects); the crash after it is checked.  Gates:
   `durack-single` (red on 2.1.0), `ackfirst`, the repro `chain3`
   reaching its bug, and `guarded`, whose backup acks from memory and
   now fails under one crash, as it should.

2. **Finite timeouts and per-node clocks** (notes item 4).  A finite
   timeout on poll, epoll_wait, select, futex, nanosleep and
   clock_nanosleep, and timerfd, is a deadline.  Each node has its own
   clock.  A world records, per node, the clock reading and the
   deadlines pending, as offsets in whole ticks; firing one is a search
   choice offered only when no earlier deadline of that node is pending
   (deadlines ordered, not one state per tick).  Clock drift is a model
   parameter (`drift = R` in parts per thousand, within the region
   abstraction: a node's clock may run up to R per thousand ahead or
   behind the reference between two events).  CLOCK_REALTIME may step
   only when the model says so.  setitimer, alarm and timer_create
   deliver signals and wait for item 3.

3. **A modelled file system** (notes item 2).  The checker owns the
   files of a node the way it owns sockets: open, openat, read, pread,
   write, pwrite, lseek, ftruncate, fsync, fdatasync, rename, unlink,
   mkdir, fstat, under a directory the model names.  Contents live in
   the world, hashed per file by content.  A crash keeps, per file, the
   last synced contents plus a chosen prefix of the writes since
   (prefix first, as ext4 data=ordered gives for appends; any subset
   and torn sectors as options).  A rename is durable only after an
   fsync of its directory.  EIO and ENOSPC are budgets, and a failed
   fsync forgets its dirty pages ("fsyncgate").  A node-wide byte
   budget, exceeded, is an error.  The fd-193 record stays as the
   simple case.

4. **Non-blocking connect and the socket surface** (notes item 5).
   EINPROGRESS, POLLOUT and getsockopt(SO_ERROR); readv, writev,
   sendmsg, recvmsg, shutdown, dup, dup2, getsockname, getpeername, and
   the setsockopt options that change nothing modelled (SO_KEEPALIVE,
   TCP_NODELAY, SO_REUSEADDR), with the others refused.  Partitions as
   a link set the search can change (`partitions = N`), asymmetric
   included.  Short writes and EAGAIN on a full send buffer as a
   budgeted choice.  Ports from the model file instead of 20000 + i.

5. **The 2.1 gaps.**  16-byte atomics and pthread_exit in the race
   runtime, and gcc's memcpy, memset and memmove calls in instrumented
   code; and/or short-circuiting in `cmc_spec.c`; an eventfd read into
   memory the checker can't write answered EFAULT as Linux does.

6. **Older items.**  TLA+ twins for fpaxos, caspaxos, zab and fastpaxos
   checked against cmc's counts by TLC; Apalache runs past `--length
   10` where the hardware allows, with the bound stated.

7. **Review.**  An independent review of `src/cmc_race.c` and of the
   argument that only lock acquisitions need be choice points.

## What waits, and why

These are the notes' items 3, 6, 7 and 8.  They are each the size of a
release, and each rests on the ones above.

- **Processes** (fork, shared memory, process-shared semaphores,
  signals, AF_UNIX and pipes; notes item 3).  The thread scheduler
  generalises: a forked child is one more scheduled entity of its node.
  The hard part is shared memory in the world.  A tree search, as for
  threads today, is sound without encoding it, and is the first step;
  canonical hashing of the pages that differ from the initial image
  (soft-dirty bits) is the second.  Signals become events delivered at
  the receiver's next interruptible point.

- **State without a hook** (notes item 6).  Hash a node's writable
  memory, registers and modelled fds into the world, with the
  deterministic allocator zeroing freed memory, and keep the hook as a
  projection for invariants only.  This also closes the
  single-threaded merge question that item 1 leaves to the hook.

- **Scale** (notes item 7).  Fork-based checkpoints of a node at each
  frontier state instead of replay from launch, hashing by dirty pages,
  DPOR, preemption and delay bounding with the bound in the verdict,
  and a parallel search.

- **History properties** (notes item 8).  Record client requests and
  responses with real-time order and check linearizability; liveness
  under a fair schedule in the process engine; a counterexample
  replayable on a real host for gdb or rr.

`--fast` stays experimental (`m9-fast-wip`, `wip/fast-read-escape`).
