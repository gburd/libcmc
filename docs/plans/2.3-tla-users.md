# Plan: what a TLA+ user needs (2.3)

A person who knows TLA+ arrives with a spec, a TLC config and habits:
TLC's options, its trace format, records and sequences in the model.
libcmc's abstract checker speaks a smaller language (`.cml`) and offers
fewer of TLC's options.  2.3 closes the gaps that cost such a user the
most, in the order below.  The rule from 2.0 holds: refused until
modelled, then exact or explicitly approximate, with a row in the
qualification table and a gate, and every new checking feature
calibrated against TLC on the same model.

## First

1. **TLC's checking options.**  A deadlock check (on by default for
   `cmc --spec`, as in TLC; `--no-deadlock` and `deadlock = off` turn it
   off), state constraints (`constraint NAME: EXPR`: a state that fails
   one is reached but not expanded) and action constraints
   (`action_constraint NAME: EXPR` over primed and unprimed variables:
   a transition that fails one is not taken).  The emitted TLA+ carries
   `CONSTRAINT` and `ACTION_CONSTRAINT` in its `.cfg`, and TLC's counts
   match.

2. **Records, sequences and named definitions in `.cml`.**  Record
   values `[a |-> 1, b |-> 2]` and field access `r.a`, `[r except !.a =
   v]`; sequences `<<1, 2>>`, `Len`, `Head`, `Tail`, `Append`, `s[i]`,
   `SubSeq`, `\o`, with a declared maximum length (bounded, so the state
   space stays finite and the fragment SMT-encodable); tuples as
   sequences; `def NAME(p, ...) = EXPR` for named operators, expanded at
   load time (no recursion).  Emitted as their TLA+ forms, with
   Apalache type annotations.

3. **Machine-readable traces.**  `--trace-format itf` writes a
   counterexample as ITF (the Informal Trace Format Apalache emits and
   its tools read), and `--trace-format json` a plain JSON array of
   states, for `cmc --spec` and for `cmc --model-file` (where each state
   is the world as the checker shows it: node records, replies, and the
   action taken).

## Then

4. **TLA+ input.**  `cmc --spec FILE.tla --config FILE.cfg`: a reader
   for the TLA+ subset `.cml` can express (one module, `EXTENDS` of the
   standard modules it needs, `CONSTANTS` bound by the `.cfg`,
   `VARIABLES`, `Init`, `Next` as a disjunction of actions, `\E`
   parameters over finite sets, invariants and the properties `.cml`
   has).  Anything outside the subset is refused (exit 3) with the
   construct named.  Gated by round trips: every `.tla` that `cmc
   --emit-tla` writes reads back to the same counts, and the hand
   written twins in `examples/spec/` read directly.
5. **TLC `.cfg` for `--spec`**: `CONSTANTS`, `INIT`/`NEXT`,
   `INVARIANT(S)`, `PROPERTY`, `CONSTRAINT`, `ACTION_CONSTRAINT`,
   `SYMMETRY` (as a permutation set), `VIEW`, `CHECK_DEADLOCK`.
6. **Fairness per action and strong fairness** (`WF_vars(A)`,
   `SF_vars(A)`), and `[][A]_v` action properties.
7. **Action coverage** for `cmc --spec`: how often each action was
   enabled and taken, as TLC's `-coverage` reports it, so a vacuous
   model shows.
8. **Spec terms in process-mode traces**: with `--refine`, each step of a
   counterexample names the abstract action it refined and the abstract
   state after it.
9. **A worked guide** from an unmodified upstream spec (Lamport's
   `Paxos.tla` or `raft.tla` from tlaplus/Examples, as far as the reader
   of item 4 takes it) to a C binary with refinement checked.
10. **Proof hooks.**  `cmc --emit-tla` writes the type invariant and,
    for an invariant the user marks `inductive`, the obligations
    `Init => Inv` and `Inv /\ Next => Inv'` as a TLAPS `THEOREM`, and
    the gate checks the inductive ones with Apalache `--inductive` where
    it is available.

## Not in 2.3

Worker threads and checkpoint and resume for `cmc --spec`, editor
support, direct SMT-LIB emission, calibration over the whole
tlaplus/Examples corpus, and full TLA+ (unbounded sets, recursion,
`CHOOSE` over infinite domains, real arithmetic).
